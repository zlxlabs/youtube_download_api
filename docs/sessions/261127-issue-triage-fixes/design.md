# 261127 Issue triage fixes：第一性原理方案

## 本批范围：4 批 6 PR

本批将问题按根因和资源边界拆为四批、六个 PR：第一批固化音频资产唯一性（本 PR，#29）与资源删除/孤儿文件 GC 对账（PR 1B，#27/#30）；后续批次分别治理任务产物与回调投影/重启恢复、以及 IP 熔断状态机。每个 PR 只改变一个明确不变量，避免把下载、回调和清理状态机混在同一变更中。

## PR 1A 不变量

- SQLite `ux_files_video_audio` 局部唯一索引是所有写入路径的最终仲裁者：每个 `video_id` 最多一条 `file_type='audio'`。
- 人工上传遇到唯一冲突返回 409；Worker 冲突复用胜出记录，标记 `reused_audio=True` 且不记录本次下载器。
- 旧库在建索引前事务内去重；任务引用先重定向到保留记录。优先保留物理文件存在者，其次人工上传，再按创建时间及 id 降序。
- `quality=None` 查询音频时不附加码率过滤条件；字幕等其他资源的筛选行为维持不变。

## 后续 PR 不变量

PR 1B 负责删除视频资源及孤儿文件 GC 对账，不由 1A 扩大删除语义。后续任务/回调批次以持久化任务事实为准，重启恢复不得重复投影；熔断批次以单一持久状态机驱动探测与退避。各批次分别增加针对状态转移和失败边界的测试。
